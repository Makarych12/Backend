# Промт для агента: превратить краткие модули в полноценный учебный курс

Ты работаешь в существующем проекте интерактивного курса «Python с нуля до Backend».
Перед изменениями полностью прочитай `PROJECT_STATUS.md`, `README.md`,
`src/pages/LessonPage.jsx` и файлы модулей, с которыми будешь работать.

## Главная проблема

Большинство модулей сейчас содержат только 3–4 урока. Это слишком мало для человека,
который изучает программирование с абсолютного нуля. Например, модуль «ООП в Python» содержит
только классы/объекты, методы и наследование. После такого объёма ученик не понимает ООП и не
готов применять его в настоящем проекте.

Старое указание «3–4 урока на модуль» отменено. Количество уроков определяется полнотой темы.
Не растягивай материал искусственно, но и не объединяй несколько больших понятий в один урок
ради маленького числа уроков.

## Цель

Последовательно расширить все модули курса так, чтобы ученик:

1. понимал тему простыми словами;
2. видел, зачем она нужна в backend-разработке;
3. писал и запускал код сам;
4. проходил путь от простого примера к реальной задаче;
5. закреплял материал практикой и мини-проектом;
6. после модуля мог объяснить тему своими словами и применить её без копирования готового ответа.

## Требуемая глубина

- Фундаментальные модули Python, ООП, HTTP, FastAPI, базы данных, SQLAlchemy, безопасность,
  тестирование, архитектура, Git и Linux: обычно **8–12 уроков**.
- Узкие прикладные модули: обычно **6–10 уроков**.
- Большие темы можно делать длиннее 12 уроков, если иначе появляются резкие скачки сложности.
- Меньше 6 уроков допустимо только после письменного обоснования в плане модуля, почему тема
  действительно узкая и полностью раскрыта.

Это ориентиры глубины, а не требование набить модуль пустыми уроками. Один урок должен решать
одну ясную учебную задачу и занимать примерно 20–40 минут вместе с практикой.

## Работай по модулям, а не по всему курсу сразу

Начни с модуля 3 «ООП в Python». Полностью закончи и проверь его, затем переходи к следующему
модулю. За один рабочий цикл расширяй один модуль. Не создавай десятки поверхностных уроков во
всех файлах одновременно.

Перед кодом для каждого модуля:

1. выпиши существующие уроки и темы, которые уже раскрыты;
2. составь карту пробелов;
3. предложи итоговую последовательность уроков от простого к сложному;
4. отметь, какие существующие уроки сохраняются, какие расширяются и какие новые добавляются;
5. проверь, что новый урок не дублирует материал соседних модулей;
6. только после этого редактируй файл модуля.

Не удаляй качественный существующий материал. Расширяй его и добавляй недостающие ступени.
Сохраняй существующие `id` уроков, чтобы не сломать сохранённый прогресс пользователей.

## Обязательный первый модуль: ООП в Python

Расширь `src/data/modules/module3.js` минимум до следующего содержательного покрытия. Названия
можно улучшить, но темы нельзя пропускать:

1. зачем нужно ООП, связь со словарями и функциями;
2. классы и объекты;
3. `__init__`, атрибуты экземпляра и `self`;
4. методы экземпляра и изменение состояния объекта;
5. атрибуты класса и отличие от атрибутов экземпляра;
6. инкапсуляция, `_name`, `__name`, геттеры/сеттеры без мистики;
7. `@property` и проверка значений;
8. наследование, `super()` и переопределение методов;
9. полиморфизм и duck typing;
10. композиция против наследования;
11. магические методы (`__str__`, `__repr__`, `__len__`, базово `__eq__`);
12. `@classmethod`, `@staticmethod` и альтернативные конструкторы;
13. базовое знакомство с `ABC`/`abstractmethod` без перегруза теорией;
14. итоговый мини-проект ООП, например система библиотеки, корзина магазина или управление
    заказами, где ученик соединяет несколько классов, композицию, свойства и полиморфизм.

Если часть тем разумно объединить, итоговый модуль всё равно должен сохранить постепенность и
полное покрытие. Нельзя превратить пункты 5–13 в один огромный урок.

## Стандарт каждого урока

Соблюдай формат из `PROJECT_STATUS.md` и поддерживаемые типы блоков `LessonPage.jsx`.
Каждый новый содержательный урок должен включать:

- понятную цель: что ученик сможет сделать после урока;
- объяснение от известного к новому без непояснённых терминов;
- бытовую аналогию для нового сложного понятия;
- пошаговую сборку кода через `type: 'steps'`;
- полный практический пример, связанный с backend или реальной программой;
- рабочую песочницу, если тему можно выполнить в Pyodide;
- минимум 3 задания по нарастающей сложности: `easy`, `medium`, `hard`;
- подсказки, которые направляют, но не сразу выдают ответ;
- решение хотя бы для сложного задания или разбор ключевой идеи решения;
- 2–4 типичные ошибки с объяснением причины;
- чек-лист из 4–7 проверяемых результатов;
- короткую связь с предыдущим и следующим уроком.

Не считай урок полноценным, если он содержит несколько абзацев теории и один готовый пример,
который ученику остаётся только запустить.

## Практика внутри модуля

В каждом расширенном модуле должны быть:

- небольшие упражнения в каждом уроке;
- не менее двух задач, где ученик пишет решение с нуля;
- одно задание на поиск и исправление ошибки;
- одно задание на чтение чужого кода и объяснение результата;
- итоговый мини-проект, объединяющий основные темы модуля;
- критерии готовности мини-проекта и пример ожидаемого поведения, но не готовое решение целиком
  до попытки ученика.

Примеры должны развиваться последовательно. Не используй в раннем уроке конструкцию, которую
курс ещё не объяснил. Если без неё нельзя обойтись, сначала добавь отдельное объяснение.

## Защита от поверхностного контента

Запрещено:

- добавлять уроки только ради количества;
- повторять один и тот же текст другими словами;
- складывать пять новых терминов в один абзац;
- писать «это очевидно», «просто сделай» или ссылаться на знания, которых у новичка ещё нет;
- давать неисполняемый код как песочницу;
- заменять практику длинной лекцией;
- менять инфраструктуру и дизайн сайта без необходимости для конкретного урока;
- помечать модуль готовым только потому, что проект собирается.

## Проверка качества

После расширения каждого модуля обязательно:

1. проверь уникальность `lesson.id` во всём курсе;
2. запусти все `sandbox.initialCode` изменённого модуля через Node + Pyodide 0.26.4 по инструкции
   из `PROJECT_STATUS.md`;
3. отдельно запусти решения заданий, содержащие код;
4. проверь Python-примеры AST-парсером, где это применимо;
5. выполни `npm run lint` и `npm run build`;
6. проверь прямое открытие каждого нового урока и навигацию «назад/вперёд»;
7. проверь отображение на ширине 360 px: код должен прокручиваться внутри блока и не расширять
   страницу;
8. вручную сопоставь результат с картой пробелов и убедись, что ни одна обязательная тема не
   потеряна.

В отчёте по каждому модулю укажи:

- сколько уроков было и сколько стало;
- какие темы добавлены;
- сколько песочниц и решений реально выполнено;
- результаты lint/build;
- известные ограничения, если они остались.

## Порядок расширения курса

После ООП проведи аудит всех модулей и расставь приоритет так:

1. фундамент, без которого непонятны следующие темы;
2. модули с 3 уроками;
3. модули, на которые ссылаются итоговые проекты;
4. остальные узкие и продвинутые темы.

Не доверяй старой фразе «модуль полностью готов», если в нём 3–4 урока. Повторно оцени полноту
по учебным результатам. Обновляй `PROJECT_STATUS.md` и `README.md` только после фактического
расширения и проверки материала. Не указывай новые числа уроков заранее.

Начни работу сейчас с аудита и расширения модуля 3 «ООП в Python».
