# План расширения модулей 1, 2 и 4

Работа ведётся по очереди: сначала модуль 1, после его проверки модуль 2, затем модуль 4. Исходные ID уроков сохраняются.

## Модуль 1 «Что такое программирование»

Сейчас 3 урока: `what-is-code` — инструкции и первый `print`; `how-computer-works` — CPU, RAM, диск; `terminal-intro` — первые команды терминала. Сохраняем все три, расширяем практику у урока про компьютер и уточняем связь терминала с файлом Python.

Пробелы: порядок выполнения и чтение вывода; различие редактора, файла, песочницы и результата; файл `.py`, папка и путь; цикл написания, запуска и исправления кода; чтение первых ошибок; самостоятельная программа из нескольких команд. Итоговый порядок: `what-is-code` → порядок инструкций (новый) → `how-computer-works` → редактор и песочница (новый) → файлы и пути (новый) → `terminal-intro` → первые ошибки (новый) → мини-проект «текстовая карточка сервиса» (новый). Переменные, условия и функции оставляем модулю 2; подробные команды Linux — модулю 32.

## Модуль 2 «Основы Python»

Сейчас 7 уроков: `variables-types`, `numbers-strings`, `conditions`, `loops`, `lists`, `dicts`, `functions`. Все сохраняем и углубляем практику. Пробелы: ввод и преобразование текста в число; булева логика и проверки с несколькими условиями; работа со строками и индексами; обход коллекций и накопление результата; ошибки и отладка; границы функций, возвращаемые значения и композиция навыков в самостоятельной программе. План: 7 существующих уроков с добавленными между ними ступенями «ввод/преобразование», «булева логика», «строки», «накопление в цикле», «ошибки» и итоговый мини-проект. Основы ООП и HTTP остаются модулям 3 и 4.

## Модуль 4 «Как работает интернет»

Сейчас 3 урока: `client-server` — роли и запрос/ответ; `http-basics` — методы и статусные группы; `rest-json` — REST-адреса и JSON. Все сохраняем, добавляем конкретику и практику. Пробелы: путь от URL через DNS к серверу; состав URL; точный вид HTTP-запроса и ответа, заголовки и тело; GET/POST/PUT/PATCH/DELETE на одном ресурсе; частые статусы и диагностика; JSON отдельно от проектирования REST; безопасность HTTPS и ограничения; самостоятельное проектирование обмена для небольшого сервиса. План: `client-server` → адрес и DNS (новый) → URL и путь (новый) → `http-basics` → структура запроса/ответа (новый) → методы и статусы на практике (новый) → `rest-json` → JSON-ошибки и преобразования (новый) → HTTPS (новый) → мини-проект API на бумаге с исполнимой локальной моделью (новый). Реализация FastAPI остаётся модулю 5.
